# Architecture — Package by Feature (Modular)

The project uses a **modular architecture (package by feature)** — each business module groups all its layers within itself.

Within each module, the flow between layers is:

```
Controller → Service → Repository → Database
```

---

## Layers (inside each module)

### controller/

Receives HTTP requests, validates input and returns responses. Contains no business logic.

### service/

Business rules, validations and financial logic.

### repository/

Data access interface using Spring Data JPA.

### model/

JPA entity representing the database table. Module-specific enums also live here.

### dto/

Transfer objects — separates input (RequestDTO) and output (ResponseDTO). The entity is never exposed directly in the API.

### mapper/

Conversion between DTO and Entity.

---

## Global Packages (shared)

Some packages remain at the root because they are cross-cutting to all modules:

| Package       | Responsibility                                    |
| ------------- | ------------------------------------------------- |
| `config/`     | Global configurations (Security, CORS, OpenAPI)   |
| `exception/`  | Global error handling and custom exceptions       |
| `util/`       | Shared utility classes                            |

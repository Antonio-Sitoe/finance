# 📚 Guia Passo a Passo: Como Implementar um CRUD

## Objetivo
Este guia te mostra exatamente como implementar uma funcionalidade CRUD (Create, Read, Update, Delete) do zero usando o exemplo prático do módulo de **Usuários** que já existe no projeto.

---

## 🏗️ Visão Geral da Arquitetura

Antes de começar, entenda que o projeto segue uma **arquitetura em camadas**:

```
┌─────────────────────────────────────────────────────────────┐
│                      REQUISIÇÃO HTTP                         │
└────────────────────────┬────────────────────────────────────┘
                         │
          ┌──────────────▼──────────────┐
          │     CONTROLLER              │
          │  (Recebe requisição)        │
          └──────────────┬──────────────┘
                         │
          ┌──────────────▼──────────────┐
          │      SERVICE                │
          │  (Lógica de negócio)        │
          └──────────────┬──────────────┘
                         │
          ┌──────────────▼──────────────┐
          │    REPOSITORY               │
          │  (Acesso ao banco de dados) │
          └──────────────┬──────────────┘
                         │
          ┌──────────────▼──────────────┐
          │      BANCO DE DADOS         │
          │      (PostgreSQL)           │
          └─────────────────────────────┘
```

**Ordem de implementação**: Model → Repository → DTOs → Mapper → Service → Controller

## ✅ Passo 1: Criar a Model (Entity)

A **Model** é a representação da tabela no banco de dados.

### Exemplo: Usuario.java

```java
package com.finance.finance.modules.auth.model;

import com.finance.finance.modules.common.baseEntity.BaseEntity;
import com.finance.finance.modules.common.enums.Perfil;
import com.finance.finance.modules.common.enums.Situacao;

import jakarta.persistence.*;
import jakarta.validation.constraints.*;
import lombok.*;

@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Entity(name = "usuario")  // Nome da tabela no banco
public class Usuario extends BaseEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;  // Chave primária (auto-incremento)

    @NotBlank(message = "O nome é obrigatório")
    @Size(max = 255, message = "O nome deve ter no máximo 255 caracteres")
    private String nome;  // Validação em tempo de criação/atualização

    @Column(unique = true)  // Email único no banco
    @NotBlank(message = "O email é obrigatório")
    @Email(message = "Email inválido")
    private String email;

    @NotBlank(message = "A senha é obrigatória")
    @Size(min = 6, max = 255, message = "A senha deve ter entre 6 e 255 caracteres")
    private String senha;

    @Enumerated(EnumType.STRING)  // Guarda como texto (ADMIN, USER)
    private Perfil perfil;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private Situacao situacao;  // ATIVO ou INATIVO
}
```

### Conceitos importantes:
- **@Entity**: Marca a classe como uma tabela no banco
- **@Id**: Chave primária da tabela
- **@GeneratedValue**: Gera ID automaticamente
- **@NotBlank, @Email, @Size**: Validações (vêm do Hibernate Validator)
- **@Enumerated**: Guarda enums no banco de dados
- **BaseEntity**: Classe que herda para ter `createdAt`, `updatedAt`, etc.

## ✅ Passo 2: Criar o Repository

O **Repository** é a interface que comunica com o banco de dados. Estende `JpaRepository` que já traz métodos prontos.

### Exemplo: UsuarioRepository.java

```java
package com.finance.finance.modules.auth.repository;

import com.finance.finance.modules.auth.model.Usuario;
import org.springframework.data.jpa.repository.JpaRepository;

public interface UsuarioRepository extends JpaRepository<Usuario, Long> {
    // JpaRepository já fornece: save(), findById(), findAll(), delete(), etc.
    
    // Métodos customizados para buscas específicas
    boolean existsByEmail(String email);
    
    boolean existsByEmailAndIdNot(String email, Long id);
}
```

### Métodos que vêm grátis do JpaRepository:
- `save(Usuario)` → Salva ou atualiza
- `findById(Long)` → Busca por ID
- `findAll()` → Busca todos
- `findAll(Pageable)` → Busca com paginação
- `delete(Usuario)` → Deleta
- `deleteById(Long)` → Deleta por ID

### Métodos customizados:
- **`existsByEmail(String email)`**: Retorna `true` se existe um usuário com esse email
- **`existsByEmailAndIdNot(String email, Long id)`**: Verifica se existe outro usuário com esse email (excluindo o ID informado)

## ✅ Passo 3: Criar os DTOs

**DTO** = Data Transfer Object. São classes que representam os dados que trafegam entre cliente e servidor.

### Por que usamos DTOs?
- **Segurança**: Não exponho todos os campos do banco
- **Validação**: Valido os dados de entrada
- **Separação**: Separo o que vem da requisição do que está no banco

### Exemplo: UsuarioRequestDTO.java (Entrada)

```java
package com.finance.finance.modules.auth.dto;

import com.finance.finance.modules.common.enums.Perfil;
import com.finance.finance.modules.common.enums.Situacao;
import jakarta.validation.constraints.*;
import lombok.Getter;
import lombok.Setter;

@Getter
@Setter
public class UsuarioRequestDTO {
    // O que eu RECEBO do cliente
    
    @NotBlank(message = "O nome é obrigatório")
    @Size(max = 255, message = "O nome deve ter no máximo 255 caracteres")
    private String nome;

    @NotBlank(message = "O email é obrigatório")
    @Email(message = "Email inválido")
    private String email;

    @NotBlank(message = "A senha é obrigatória")
    @Size(min = 6, max = 255, message = "A senha deve ter entre 6 e 255 caracteres")
    private String senha;

    @NotNull(message = "O perfil é obrigatório")
    private Perfil perfil;

    @NotNull(message = "A situação é obrigatória")
    private Situacao situacao;
}
```

### Exemplo: UsuarioResponseDTO.java (Saída)

```java
package com.finance.finance.modules.auth.dto;

import com.finance.finance.modules.common.enums.Perfil;
import com.finance.finance.modules.common.enums.Situacao;
import lombok.Builder;
import lombok.Getter;
import lombok.Setter;

import java.time.LocalDateTime;

@Getter
@Setter
@Builder
public class UsuarioResponseDTO {
    // O que eu RETORNO para o cliente
    
    private Long id;
    private String nome;
    private String email;
    private Perfil perfil;
    private Situacao situacao;
    private LocalDateTime createdAt;
    
    // NÃO exponho: senha, updatedAt, etc.
}
```

### Diferenças:
- **RequestDTO**: O que o cliente envia (POST/PUT)
- **ResponseDTO**: O que o servidor retorna (respostas)
- Ambas têm validações, mas podem ter campos diferentes

## ✅ Passo 4: Criar o Mapper

O **Mapper** converte dados entre entidades e DTOs.

### Exemplo: UsuarioMapper.java

```java
package com.finance.finance.modules.auth.mapper;

import com.finance.finance.modules.auth.dto.UsuarioRequestDTO;
import com.finance.finance.modules.auth.dto.UsuarioResponseDTO;
import com.finance.finance.modules.auth.model.Usuario;

public final class UsuarioMapper {

    private UsuarioMapper() {
        // Construtor privado para evitar instanciação
    }

    // DTO → Entity (quando recebo dados do cliente)
    public static Usuario toEntity(UsuarioRequestDTO dto) {
        Usuario usuario = new Usuario();
        usuario.setNome(dto.getNome());
        usuario.setEmail(dto.getEmail());
        usuario.setSenha(dto.getSenha());
        usuario.setPerfil(dto.getPerfil());
        usuario.setSituacao(dto.getSituacao());
        return usuario;
    }

    // Atualizar Entity com dados do DTO
    public static void updateEntity(Usuario usuario, UsuarioRequestDTO dto) {
        usuario.setNome(dto.getNome());
        usuario.setEmail(dto.getEmail());
        usuario.setSenha(dto.getSenha());
        usuario.setPerfil(dto.getPerfil());
        usuario.setSituacao(dto.getSituacao());
    }

    // Entity → DTO (quando retorno dados para o cliente)
    public static UsuarioResponseDTO toResponseDTO(Usuario usuario) {
        return UsuarioResponseDTO.builder()
                .id(usuario.getId())
                .nome(usuario.getNome())
                .email(usuario.getEmail())
                .perfil(usuario.getPerfil())
                .situacao(usuario.getSituacao())
                .createdAt(usuario.getCreatedAt())
                .build();
    }
}
```

### Por que preciso de Mapper?
- Converte `UsuarioRequestDTO` → `Usuario` (para salvar no banco)
- Converte `Usuario` → `UsuarioResponseDTO` (para enviar para o cliente)
- Deixa a lógica de conversão organizada e reutilizável

## ✅ Passo 5: Criar a Service

A **Service** contém toda a **lógica de negócio**. É aqui que a mágica acontece!

### Exemplo: UsuarioService.java

```java
package com.finance.finance.modules.auth.service;

import com.finance.finance.modules.auth.dto.UsuarioRequestDTO;
import com.finance.finance.modules.auth.dto.UsuarioResponseDTO;
import com.finance.finance.modules.auth.mapper.UsuarioMapper;
import com.finance.finance.modules.auth.model.Usuario;
import com.finance.finance.modules.auth.repository.UsuarioRepository;
import com.finance.finance.modules.common.enums.Situacao;
import com.finance.finance.modules.common.pagination.PageResponse;
import com.finance.finance.modules.common.pagination.PaginationRequest;
import com.finance.finance.exceptions.BusinessException;
import com.finance.finance.exceptions.ResourceNotFoundException;
import lombok.RequiredArgsConstructor;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service  // Marca como serviço (Spring vai gerenciar)
@RequiredArgsConstructor  // Cria construtor com as dependências
@Transactional  // Todas as operações serão transacionais
public class UsuarioService {

    private final UsuarioRepository usuarioRepository;
    private final PasswordEncoder passwordEncoder;

    // ============ CREATE ============
    public UsuarioResponseDTO criar(UsuarioRequestDTO dto) {
        // 1. Validar se email já existe
        validarEmailUnico(dto.getEmail(), null);
        
        // 2. Converter DTO para Entity
        Usuario usuario = UsuarioMapper.toEntity(dto);
        
        // 3. Criptografar senha (IMPORTANTE!)
        usuario.setSenha(passwordEncoder.encode(dto.getSenha()));
        
        // 4. Salvar no banco
        usuarioRepository.save(usuario);
        
        // 5. Retornar como ResponseDTO
        return UsuarioMapper.toResponseDTO(usuario);
    }

    // ============ UPDATE ============
    public UsuarioResponseDTO atualizar(Long id, UsuarioRequestDTO dto) {
        // 1. Buscar usuário existente (falha se não encontrar)
        Usuario usuario = buscarOuFalhar(id);
        
        // 2. Validar email (mas pode ter o mesmo email se for o mesmo usuário)
        validarEmailUnico(dto.getEmail(), id);
        
        // 3. Atualizar os dados
        UsuarioMapper.updateEntity(usuario, dto);
        
        // 4. Criptografar nova senha
        usuario.setSenha(passwordEncoder.encode(dto.getSenha()));
        
        // 5. Salvar
        usuarioRepository.save(usuario);
        
        // 6. Retornar
        return UsuarioMapper.toResponseDTO(usuario);
    }

    // ============ DELETE (Soft Delete) ============
    public void desativar(Long id) {
        // Não deletamos de verdade, apenas marcamos como INATIVO
        Usuario usuario = buscarOuFalhar(id);
        usuario.setSituacao(Situacao.INATIVO);
        usuarioRepository.save(usuario);
    }

    // ============ READ (Listar com Paginação) ============
    @Transactional(readOnly = true)  // Apenas leitura, mais eficiente
    public PageResponse<UsuarioResponseDTO> listar(PaginationRequest paginationRequest) {
        // 1. Converter request de paginação
        Pageable pageable = paginationRequest.toPageable("id");
        
        // 2. Buscar página
        Page<UsuarioResponseDTO> page = usuarioRepository.findAll(pageable)
                .map(UsuarioMapper::toResponseDTO);
        
        // 3. Retornar com informações de paginação
        return PageResponse.from(page);
    }

    // ============ READ (Buscar por ID) ============
    @Transactional(readOnly = true)
    public UsuarioResponseDTO buscarPorId(Long id) {
        return UsuarioMapper.toResponseDTO(buscarOuFalhar(id));
    }

    // ============ MÉTODOS AUXILIARES ============
    
    // Busca no banco, falha se não encontrar
    private Usuario buscarOuFalhar(Long id) {
        return usuarioRepository.findById(id)
                .orElseThrow(() -> new ResourceNotFoundException(
                    "Usuário não encontrado com id: " + id
                ));
    }

    // Valida se email é único
    private void validarEmailUnico(String email, Long idAtual) {
        boolean emailEmUso = idAtual == null
                ? usuarioRepository.existsByEmail(email)
                : usuarioRepository.existsByEmailAndIdNot(email, idAtual);

        if (emailEmUso) {
            throw new BusinessException(
                "Já existe um usuário cadastrado com este email"
            );
        }
    }
}
```

### Conceitos importantes:

| Conceito | Explicação |
|----------|-----------|
| `@Service` | Marca a classe como serviço do Spring |
| `@RequiredArgsConstructor` | Gera construtor com dependências (injeção) |
| `@Transactional` | Todas operações são transacionais (rollback automático em erro) |
| `@Transactional(readOnly = true)` | Otimização para apenas leitura |
| `validarEmailUnico()` | Método privado (helper) para validações |
| `buscarOuFalhar()` | Método privado que busca ou lança exceção |

## ✅ Passo 6: Criar o Controller

O **Controller** é o ponto de entrada das requisições HTTP. Recebe os dados e chama a Service.

### Exemplo: UsuarioController.java

```java
package com.finance.finance.modules.auth.controller;

import com.finance.finance.modules.auth.dto.UsuarioRequestDTO;
import com.finance.finance.modules.auth.dto.UsuarioResponseDTO;
import com.finance.finance.modules.auth.service.UsuarioService;
import com.finance.finance.modules.common.pagination.PageResponse;
import com.finance.finance.modules.common.pagination.PaginationRequest;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

@RestController  // Marca como controller REST (retorna JSON)
@RequestMapping("/usuarios")  // URL base: localhost:8080/usuarios
@RequiredArgsConstructor  // Injeção de dependência
public class UsuarioController {

    private final UsuarioService usuarioService;

    // ============ CREATE ============
    @PostMapping  // POST /usuarios
    public ResponseEntity<UsuarioResponseDTO> criar(
            @RequestBody @Valid UsuarioRequestDTO dto) {
        // @RequestBody: converte JSON da requisição em DTO
        // @Valid: valida o DTO usando anotações (ex: @NotBlank)
        
        UsuarioResponseDTO response = usuarioService.criar(dto);
        
        // Retorna 201 Created
        return ResponseEntity.status(HttpStatus.CREATED).body(response);
    }

    // ============ UPDATE ============
    @PutMapping("/{id}")  // PUT /usuarios/1
    public ResponseEntity<UsuarioResponseDTO> atualizar(
            @PathVariable Long id,  // Vem da URL
            @RequestBody @Valid UsuarioRequestDTO dto) {  // Vem do corpo
        
        UsuarioResponseDTO response = usuarioService.atualizar(id, dto);
        
        // Retorna 200 OK
        return ResponseEntity.ok(response);
    }

    // ============ DELETE ============
    @DeleteMapping("/{id}")  // DELETE /usuarios/1
    @ResponseStatus(HttpStatus.NO_CONTENT)  // Retorna 204 No Content
    public void desativar(@PathVariable Long id) {
        usuarioService.desativar(id);
    }

    // ============ READ (Listar) ============
    @GetMapping  // GET /usuarios?page=0&size=10
    public ResponseEntity<PageResponse<UsuarioResponseDTO>> listar(
            @Valid @ModelAttribute PaginationRequest paginationRequest) {
        // @ModelAttribute: converte parâmetros da query string em objeto
        
        PageResponse<UsuarioResponseDTO> response = usuarioService.listar(paginationRequest);
        
        // Retorna 200 OK
        return ResponseEntity.ok(response);
    }

    // ============ READ (Buscar por ID) ============
    @GetMapping("/{id}")  // GET /usuarios/1
    public ResponseEntity<UsuarioResponseDTO> buscarPorId(@PathVariable Long id) {
        UsuarioResponseDTO response = usuarioService.buscarPorId(id);
        
        // Retorna 200 OK
        return ResponseEntity.ok(response);
    }
}
```

### Mapeamento de endpoints:

| Método | URL | HTTP | Ação |
|--------|-----|------|------|
| `criar()` | `/usuarios` | POST | Cria novo usuário |
| `listar()` | `/usuarios?page=0&size=10` | GET | Lista com paginação |
| `buscarPorId()` | `/usuarios/1` | GET | Busca específico |
| `atualizar()` | `/usuarios/1` | PUT | Atualiza usuário |
| `desativar()` | `/usuarios/1` | DELETE | Desativa usuário |

## 📋 Checklist para Implementar um Novo CRUD

Quando for implementar um novo módulo (ex: Cliente, Fornecedor), siga este checklist:

### 1. **Criar Model** (pasta `model/`)
- [ ] Criar classe com `@Entity`
- [ ] Adicionar `@Id @GeneratedValue`
- [ ] Adicionar validações (`@NotBlank`, `@Email`, etc.)
- [ ] Estender `BaseEntity` para ter `createdAt`, `updatedAt`

### 2. **Criar Repository** (pasta `repository/`)
- [ ] Criar interface que estende `JpaRepository<Model, Long>`
- [ ] Adicionar métodos de busca customizados se necessário

### 3. **Criar DTOs** (pasta `dto/`)
- [ ] Criar `RequestDTO` com validações
- [ ] Criar `ResponseDTO` sem campos sensíveis

### 4. **Criar Mapper** (pasta `mapper/`)
- [ ] Método `toEntity()`: DTO → Model
- [ ] Método `updateEntity()`: atualizar Model
- [ ] Método `toResponseDTO()`: Model → DTO

### 5. **Criar Service** (pasta `service/`)
- [ ] Marcar com `@Service` e `@RequiredArgsConstructor`
- [ ] Injetar Repository
- [ ] Implementar: `criar()`, `atualizar()`, `desativar()`, `listar()`, `buscarPorId()`
- [ ] Adicionar validações de negócio
- [ ] Tratar exceções apropriadas

### 6. **Criar Controller** (pasta `controller/`)
- [ ] Marcar com `@RestController` e `@RequestMapping`
- [ ] Endpoints: POST, PUT, DELETE, GET, GET/{id}
- [ ] Usar `@Valid` para validar DTOs
- [ ] Retornar `ResponseEntity` com status HTTP apropriado

## 🎓 Dicas de Aprendizado

### 1. **Estude o fluxo**
Entenda que dados trafegam de:
```
HTTP Request → Controller → Service → Repository → Banco → Repository → Service → Controller → HTTP Response
```

### 2. **Separação de responsabilidades**
- **Controller**: Recebe/retorna HTTP
- **Service**: Lógica de negócio
- **Repository**: Acesso ao banco
- **Mapper**: Conversão de dados
- **DTO**: Comunicação

### 3. **Validações em camadas**
```
DTO (validações básicas) → Service (validações de negócio) → Banco (constraints)
```

### 4. **Sempre use DTOs**
Nunca retorne a Entity direto! Sempre use DTO para:
- Não expor campos sensíveis (senha, etc.)
- Ter validações apropriadas
- Flexibilidade para mudanças

### 5. **Tratamento de erros**
- `BusinessException`: Erros de negócio (email duplicado, saldo insuficiente)
- `ResourceNotFoundException`: Recurso não encontrado (usuário não existe)
- `ValidationException`: Dados inválidos (vem automático do `@Valid`)

### 6. **Testes**
Para cada método na Service, crie um teste:
```java
@Test
void criarUsuarioValido() { ... }

@Test
void criarUsuarioEmailDuplicado() { ... }

@Test
void buscarUsuarioNaoExistente() { ... }
```
